## Схема из трёх узлов

```text
  Vue 3 + Vite                    FastAPI (Python)                 PostgreSQL
  localhost:5173   ───────────►   localhost:5000    ───────────►   localhost:5432
                       HTTP                            SQL через ORM
         POST /api/publication-requests          INSERT INTO publication_requests
```

**архитектура web-ИС семестра**

Прямой стрелки от браузера к базе нет.

## Что делает каждый узел

| Узел | Порт | Отвечает за |
|------|------|-------------|
| Клиент: Vue 3 + Vite | `5173` | три экрана (список заявок, создание заявки, вход); отправляет HTTP-запросы к API и показывает ответ |
| Сервер: FastAPI (Python) | `5000` | проверяет поля (`400`), правила процесса (`409`: переходы статуса, заявка без редактора), позже — вход и роли (`401`/`403`); задаёт `id`, `number`, `status` |
| База: PostgreSQL | `5432` | хранит таблицы `departments`, `users`, `publication_requests`; `CHECK` на статусы и роли, внешние ключи |

Запуск сервера на порту курса: `uvicorn app.main:app --port 5000`. Сервер разрешает запросы с `http://localhost:5173` (CORS).

## Почему браузер не ходит в PostgreSQL напрямую

- Клиенту пришлось бы отдать логин и пароль от базы — их увидит любой пользователь в инструментах браузера.
- Клиент обошёл бы правила сервера: смог бы поставить `Closed` без редактора или изменить чужую заявку.
- Все проверки (длина полей, переходы статуса, права ролей) живут в одном месте — на сервере, а не в каждом клиенте.

## Что добавится в ВКР

ИИ-модуль (индексация материалов и ответы на вопросы) встанет за тем же API, рядом с FastAPI. Браузер по-прежнему общается только с API, а векторный индекс хранится в той же PostgreSQL (pgvector).
