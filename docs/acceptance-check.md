## Как проводить проверку

1. Поднять стенд по README с чистого места.
2. Выполнить сценарий ниже на **одной** заявке.
3. Записать её `id` и `number` и показать один и тот же id в трёх местах: экран, Network, SQL.

Запрос для SQL-доказательства:

```sql
SELECT id, number, title, status, assignee_user_id
FROM publication_requests
WHERE id = 10;
```

## Критерий 1. Создать заявку

| Поле | Значение |
|---|---|
| **Дано** | автор вошёл в систему (`author`) |
| **Когда** | заполняет заголовок (5–80), подразделение из списка, описание (10–500) и нажимает «Создать» |
| **Тогда** | `POST /api/publication-requests` → `201`, в ответе `id`, `number` вида `БЗ-2026-0001`, `status: "New"`, `assigneeUserId: null` |
| **Экран** | строка появилась в списке со статусом «Поступила» |
| **Network** | POST → 201 |
| **SQL** | строка с тем же id, `status = 'New'`, `assignee_user_id IS NULL` |
| **Факт** | `POST /api/publication-requests` → **201 Created**, заголовок ответа `Location: http://localhost:5000/api/publication-requests/10`. В теле `id = 10`, `number = "БЗ-2026-0010"`, `status = "New"`, `assigneeUserId = null`. Экран: строка «Проверка критериев приемки ЛР12», статус «Поступила», редактор «не назначен». SQL: `10 · БЗ-2026-0010 · New · assignee_user_id NULL`. |

## Критерий 2. Назначить редактора

| Поле | Значение |
|---|---|
| **Дано** | координатор вошёл (`coordinator`), заявка в статусе `New` |
| **Когда** | выбирает редактора в строке заявки |
| **Тогда** | `PATCH /api/publication-requests/{id}/assignee` → `200`, `assigneeUserId` записан, **статус не изменился** |
| **Экран** | в строке виден выбранный редактор, статус прежний |
| **Network** | PATCH `/assignee` → 200 |
| **SQL** | `assignee_user_id` у того же id не NULL, `status = 'New'` |
| **Факт** | `PATCH /api/publication-requests/10/assignee` → **200**. SQL: `assignee_user_id = 3` (`login = editor`), `status` по-прежнему `New`. Экран: в столбце «Редактор» — «Редактор базы знаний», статус остался «Поступила». |

## Критерий 3. Взять в работу

| Поле | Значение |
|---|---|
| **Дано** | назначенный редактор вошёл (`editor`) |
| **Когда** | нажимает «Взять на проверку» |
| **Тогда** | `PATCH /api/publication-requests/{id}/status` → `200`, статус `InProgress` |
| **Экран** | статус «На проверке» |
| **Network** | PATCH `/status` → 200 |
| **SQL** | `status = 'InProgress'` у того же id |
| **Факт** | `PATCH /api/publication-requests/10/status` → **200**. SQL: `status = 'InProgress'`. Экран: «На проверке», кнопки строки сменились на «Опубликовать» и «Отклонить». |

## Область видимости списка

Проверка требований ФТ-4, ФТ-5 и ФТ-8: список зависит от роли вошедшего.
Для проверки в базу добавлена заявка `БЗ-2026-0099` с `created_by_user_id = 2`
(координатор), то есть заведомо чужая для автора.

| Роль | Ожидание | Факт |
|---|---|---|
| `author` (id 1) | только свои заявки (ФТ-4) | видит `0001`, `0003`, `0004`; `БЗ-2026-0099` в списке отсутствует |
| `coordinator` (id 2) | все заявки (ФТ-5) | видит все четыре, включая `БЗ-2026-0099` |
| `editor` (id 3) | только назначенные ему (ФТ-8) | видит только `БЗ-2026-0001`; после переназначения `0010` на `editor2` эта заявка из списка исчезла |

Отбор выполняет сервер: условие по роли уходит в `WHERE` запроса,
поэтому тот же запрос через Swagger возвращает ровно те же строки.

## Фильтры списка (ФТ-5)

| Запрос | Ожидание | Факт |
|---|---|---|
| `?status=New` под координатором | только заявки в статусе `New` | три заявки: `0099`, `0004`, `0003` |
| `?departmentId=1` под координатором | только «Учебный отдел» | четыре заявки; `0004` («Студенческий городок») исключена |
| `?status=New` под редактором | пересечение роли и фильтра | `[]` — у редактора единственная заявка в статусе `Closed`. Пустой список — это `200` и `[]`, а не `404` |
| `?status=Banana` | `400` | `{"error":"validation","fields":{"status":"Неизвестный статус. Допустимы: New, InProgress, Closed, Cancelled"}}` |

## Названия в ответе API

| Проверка | Ожидание | Факт |
|---|---|---|
| в объекте заявки есть названия, а не только идентификаторы | `departmentName`, `createdByFullName`, `assigneeFullName` | `"departmentName":"Учебный отдел"`, `"createdByFullName":"Сотрудник учебного отдела"`, `"assigneeFullName":"Второй редактор базы знаний"`; у заявки без редактора `assigneeFullName: null` |

## Проверки запретов

| Проверка | Ожидание | Факт |
|---|---|---|
| запрос без входа | `401`, тело `{"error":"unauthorized"}` | `GET /api/auth/me` и `PATCH /api/publication-requests/3/status` без сессии → **401**, `{"error":"unauthorized","message":"Нужно войти в систему"}` |
| автор назначает редактора | `403` | `PATCH /api/publication-requests/3/assignee` под `author` → **403**, `{"error":"forbidden","message":"Недостаточно прав для этого действия"}` |
| координатор меняет статус | `403` | `PATCH /api/publication-requests/3/status` под `coordinator` → **403**, то же сообщение |
| редактор двигает чужую заявку | `403` | заявка `10` переназначена на `editor2`; под `editor` она пропала из списка, а `PATCH /api/publication-requests/10/status` в Swagger → **403**, «Статус меняет только редактор, назначенный на эту заявку» |
| статус `InProgress` без назначенного редактора | `409` | `PATCH /api/publication-requests/3/status` → **409**, «Сначала назначьте редактора: без него заявку нельзя двигать» |
| заголовок из 3 символов | `400`, ошибка по полю `title` | `POST` с `"title":"abc"` → **400**, `{"fields":{"title":"От 5 до 80 символов"}}` |
| неизвестный статус `Done` | `400` | `PATCH …/10/status` с `{"status":"Done"}` → **400**, `{"fields":{"status":"Статус: New, InProgress, Closed или Cancelled"}}` |
| `GET /api/publication-requests/999999` | `404` | **404**, `{"error":"not_found","message":"Заявка 999999 не найдена"}` |

Два запрета возвращают `403` по разным причинам, и это видно по сообщению:
роль не подходит — проверяет атрибут `[Authorize(Roles = …)]`, заявка чужая —
проверяет `PublicationRequestService.ChangeStatus`. Конверт ответа одинаковый.

## Ограничения на уровне базы

Длины полей проверяет не только DTO, но и сама таблица.

| Проверка | Ожидание | Факт |
|---|---|---|
| `INSERT` напрямую в базу с описанием из 8 символов | ошибка ограничения | `ERROR: new row for relation "publication_requests" violates check constraint "publication_requests_description_check"`, SQL state `23514` |
