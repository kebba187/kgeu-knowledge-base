## Как проводить проверку

1. Поднять стенд по README с чистого места.
2. Выполнить сценарий ниже на **одной** заявке.
3. Записать её `id` и `number` и показать один и тот же id в трёх местах: экран, Network, SQL.

Запрос для SQL-доказательства:

```sql
SELECT id, number, title, status, assignee_user_id
FROM publication_requests
WHERE id = __;
```

## Критерий 1. Создать заявку

| Поле | Значение |
|---|---|
| **Дано** | автор вошёл в систему (`author`) |
| **Когда** | заполняет заголовок (5–80), подразделение числом, описание (10–500) и нажимает «Создать» |
| **Тогда** | `POST /api/publication-requests` → `201`, в ответе `id`, `number` вида `БЗ-2026-0001`, `status: "New"`, `assigneeUserId: null` |
| **Экран** | строка появилась в списке со статусом «Поступила» |
| **Network** | POST → 201 |
| **SQL** | строка с тем же id, `status = 'New'`, `assignee_user_id IS NULL` |
| **Факт** | заполнить при прогоне |

## Критерий 2. Назначить редактора

| Поле | Значение |
|---|---|
| **Дано** | координатор вошёл (`coordinator`), заявка в статусе `New` |
| **Когда** | выбирает редактора в строке заявки |
| **Тогда** | `PATCH /api/publication-requests/{id}/assignee` → `200`, `assigneeUserId` записан, **статус не изменился** |
| **Экран** | в строке виден выбранный редактор, статус прежний |
| **Network** | PATCH `/assignee` → 200 |
| **SQL** | `assignee_user_id` у того же id не NULL, `status = 'New'` |
| **Факт** | заполнить при прогоне |

## Критерий 3. Взять в работу

| Поле | Значение |
|---|---|
| **Дано** | назначенный редактор вошёл (`editor`) |
| **Когда** | нажимает «Взять на проверку» |
| **Тогда** | `PATCH /api/publication-requests/{id}/status` → `200`, статус `InProgress` |
| **Экран** | статус «На проверке» |
| **Network** | PATCH `/status` → 200 |
| **SQL** | `status = 'InProgress'` у того же id |
| **Факт** | заполнить при прогоне |

## Проверки запретов

| Проверка | Ожидание | Факт |
|---|---|---|
| `POST` заявки без входа | `401`, тело `{"error":"unauthorized"}` | |
| автор назначает редактора | `403` | |
| координатор меняет статус | `403` | |
| редактор двигает чужую заявку | `403` | |
| статус `InProgress` без назначенного редактора | `409` | |
| заголовок из 3 символов | `400`, ошибка по полю `title` | |
| неизвестный статус `Done` | `400` | |
| `GET /api/publication-requests/999999` | `404` | |

## Сохранность после рестарта

| Шаг | Ожидание | Факт |
|---|---|---|
| остановить API `Ctrl+C` | — | |
| запустить `dotnet run` | сервер слушает `:5000` | |
| `GET /api/publication-requests/{id}` | `200`, те же `number`, `title`, `status` | |

Данные лежат в PostgreSQL, поэтому перезапуск процесса их не теряет. Потеря данных после F5 была ожидаемой только до ЛР6 включительно.

| Проверка | Ожидание | Факт |
|---|---|---|
| создать заявку с описанием `<script>alert(1)</script>` | текст виден символами, окно `alert` не появляется | |
