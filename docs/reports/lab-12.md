## 1. Цель

Стенд работает целиком: React на `:5173`, ASP.NET Core на `:5000`, PostgreSQL на `:5432`. Один и тот же номер заявки виден на экране, в Network и в таблице базы. Три критерия из ТЗ проходят без ручных правок в базе.

## 2. Что сделали

1. Клиент переведён с mock на настоящий API: `VITE_USE_MOCK=false` в `frontend/.env`, адрес берётся из `VITE_API_BASE_URL`.
2. Все запросы идут с `credentials: "include"`, поэтому cookie сессии уходит на порт 5000.
3. CORS на сервере разрешает один источник — `http://localhost:5173` — с `AllowCredentials`.
4. В таблице появились действия по роли: координатор выбирает редактора, назначенный редактор переводит заявку «Взять на проверку», «Опубликовать», «Отклонить».
5. Описание заявки выводится под заголовком — на этом же месте видно, что HTML из описания не выполняется.
6. Добавлены `docs/acceptance-check.md` (прогон трёх критериев) и `docs/known-defects.md` (ограничения).
7. README переписан как инструкция поставки: версии, база, секрет, миграции, запуск, учебные логины, проверочный сценарий.

## 3. Порты и режимы

| Узел | Адрес | Как запускается |
|---|---|---|
| React + Vite | `http://localhost:5173` | `npm run dev` |
| ASP.NET Core | `http://localhost:5000` | `dotnet run` |
| PostgreSQL | `localhost:5432` | служба ОС |

`VITE_USE_MOCK=true` оставлен как запасной режим работы без сервера; в рабочем сценарии он выключен.

## 4. Доказательство успеха — один id в трёх местах

Прогон на стенде: id = ____ · number = ____

| Где | Что показать | Факт |
|---|---|---|
| UI | строка заявки со статусом | |
| Network | `POST /api/publication-requests` → `201`, `id` в Response | |
| SQL | `SELECT id, number, title, status, assignee_user_id FROM publication_requests WHERE id = __;` | |
| после рестарта API | `GET /api/publication-requests/{id}` → `200` | |

Последовательность запросов, снятая в браузере во время прогона:

```text
автор:        POST /api/auth/login              → 200
автор:        POST /api/publication-requests    → 201
координатор:  POST /api/auth/login              → 200
координатор:  GET  /api/users?role=Editor       → 200
координатор:  PATCH /api/publication-requests/1/assignee → 200
редактор:     POST /api/auth/login              → 200
редактор:     PATCH /api/publication-requests/1/status   → 200
```

## 6. Признаки CORS-проблемы (на случай повторения)

- запрос виден в Network, но приложение не получает ответ;
- Swagger на `:5000` при этом работает;
- в консоли сообщение про CORS;
- это не обычный `500`.

Лечение: в `Program.cs` политика `client` должна содержать точный origin `http://localhost:5173` и `AllowCredentials`, а клиент — отправлять `credentials: "include"`.
