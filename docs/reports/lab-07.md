## 1. Цель

В том же репозитории появляется `backend/` — приложение ASP.NET Core 8, которое слушает `http://localhost:5000`, открывает Swagger в режиме Development и отвечает на служебные адреса `/health` и `/info`. Создание заявок в этой работе не делается.

## 2. Что сделали

1. Создан проект `backend/` рядом с `frontend/` (`dotnet new webapi --use-controllers`).
2. HTTP-порт зафиксирован в `backend/Properties/launchSettings.json`: `http://localhost:5000`.
3. Подключены Swagger и описание API: `AddEndpointsApiExplorer`, `AddSwaggerGen`, `UseSwagger`, `UseSwaggerUI` — только в Development.
4. Добавлен `Controllers/ServiceController.cs` с `GET /health` и `GET /info`.
5. Созданы слои `Controllers`, `Services`, `Models`, `Data`.
6. Заведены `Models/PublicationRequest.cs` и `Models/RequestStatus.cs` — заготовка главного объекта и четыре статуса курса.
7. Хранилище скрыто за интерфейсом `Services/IPublicationRequestStore.cs`; реализация `InMemoryPublicationRequestStore` зарегистрирована в `Program.cs`.
8. В `.gitignore` добавлены `**/bin/` и `**/obj/`.
9. В README записаны команды запуска и ограничения работы.

> Сервис зарегистрирован через DI, чтобы контроллер не создавал реализацию через `new`.

## 5. Чеклист «/health ≠ создание»

| Утверждение | да/нет |
|---|---|
| `/health` возвращает `200` без тела заявки | да |
| `/health` не принимает `title`, `departmentId`, `description` | да, метод POST не поддерживается |
| Успешный `/health` не доказывает работу POST | да: маршрута создания ещё нет |
| Создание главного объекта относится к ЛР8 | да |
| README прямо объясняет это различие | да |
| Swagger и `/health` проверены отдельно | да |

## 8. Ответы к защите

1. **Чем C# отличается от ASP.NET Core?** C# — язык, на котором написаны файлы `.cs`. ASP.NET Core — web-фреймворк поверх .NET: он принимает HTTP-запросы, маршрутизирует их и формирует ответы.
2. **Зачем DI, если можно написать `new`?** При `new` контроллер жёстко привязан к одной реализации. Через DI в `Program.cs` указана одна строка: сегодня список в памяти, в ЛР10 — PostgreSQL, и контроллер не меняется.
3. **Что доказывает успешный `/health`?** Только то, что процесс запущен и маршрут отвечает. Ни создание заявки, ни проверка полей, ни база данных этим не проверяются.
4. **Почему создание заявки ещё не готово?** В ЛР7 делается каркас: порт, Swagger, слои и регистрация зависимостей. Маршруты главного объекта — задача ЛР8.
