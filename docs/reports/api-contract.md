## Таблица API

| Метод и путь | Тело | Успех | Возможная ошибка |
|--------------|------|-------|------------------|
| `GET /api/publication-requests` | — (необязательные фильтры в строке запроса: `?status=New&departmentId=1`) | `200`, массив или `[]` | `400` — неизвестный `status` в фильтре |
| `GET /api/publication-requests/{id}` | — | `200`, объект | `404` |
| `POST /api/publication-requests` | `title`, `departmentId`, `description` | `201`, объект: `id`, `number`, `status: New`, `assigneeUserId: null` | `400` |
| `PATCH /api/publication-requests/{id}/assignee` | `assigneeUserId` | `200`, объект | `400`, `404`, `409` |
| `PATCH /api/publication-requests/{id}/status` | `status` | `200`, объект | `400`, `404`, `409` |
| `GET /api/departments` | — | `200`, массив подразделений | — |
| `GET /api/users?role=Editor` | — | `200`, массив редакторов (`id`, `fullName`) | `400` — неизвестная роль |

- Клиент **не присылает** при создании `id`, `number`, `status`, `assigneeUserId` и `createdByUserId`. Их задаёт сервер.
- Назначение редактора и смена статуса — **два разных `PATCH`**. Общего `PATCH /update` нет.
- **`DELETE` нет.** Отклонить заявку — `PATCH …/status` со значением `Cancelled`; строка остаётся в базе.
- Пути без глаголов: создание — `POST /api/publication-requests`, а не `…/create`.
- Пустой список — `200` и `[]`, а не `404`.

## Статусы

Только четыре кода, в API и в БД одинаковые:

| Код | На экране | Смысл |
|-----|-----------|-------|
| `New` | Поступила | заявку создали |
| `InProgress` | На проверке | редактор взял материал на проверку |
| `Closed` | Опубликовано | материал проверен и опубликован |
| `Cancelled` | Отклонено | материал не публикуется |

### Допустимые переходы (`PATCH …/status`)

| Из \ В | `InProgress` | `Closed` | `Cancelled` |
|--------|--------------|----------|-------------|
| `New` | `200` | `409` | `200` |
| `InProgress` | `409` | `200` | `200` |
| `Closed` | `409` | `409` | `409` |
| `Cancelled` | `409` | `409` | `409` |

Дополнительно:

- переход в `New` и «тот же статус» → `409`;
- смена статуса, пока нет редактора (`assigneeUserId` = `null`) → `409`;
- значение не из четырёх кодов (например, `"Done"`) → `400`.

### Правила назначения (`PATCH …/assignee`)

- `assigneeUserId` не существует или это не редактор → `400`;
- заявка уже `Closed` или `Cancelled` → `409`;
- в статусах `New` и `InProgress` редактора можно сменить → `200`. Статус при этом не меняется.

## Коды ответов

| Код | Когда |
|-----|-------|
| `200` | прочитали или изменили |
| `201` | создали заявку |
| `400` | прислали некорректные данные (длина, тип, неизвестный код) |
| `404` | заявки с таким `id` нет |
| `409` | действие противоречит правилам процесса (запрещённый переход, нет редактора) |

Ошибки возвращаются в одном формате, без stack trace:

```json
{ "error": "validation", "message": "Проверьте поля", "fields": { "title": "От 5 до 80 символов" } }
```

> ASP.NET Core по умолчанию отвечает на ошибки валидации кодом `400`, но в формате `ProblemDetails`. В проекте ответ приведён к формату выше через `ApiBehaviorOptions.InvalidModelStateResponseFactory`.

## Примеры JSON

### Создать заявку

`POST /api/publication-requests`

```json
{
  "title": "Порядок оформления академического отпуска",
  "departmentId": 1,
  "description": "Опубликовать порядок по новому положению: какие документы нужны, куда подавать и в какой срок рассматривают."
}
```

Ответ `201 Created`:

```json
{
  "id": 1,
  "number": "БЗ-2026-0001",
  "title": "Порядок оформления академического отпуска",
  "description": "Опубликовать порядок по новому положению: какие документы нужны, куда подавать и в какой срок рассматривают.",
  "status": "New",
  "departmentId": 1,
  "createdByUserId": 2,
  "assigneeUserId": null,
  "createdAt": "2026-09-21T10:15:00Z",
  "updatedAt": "2026-09-21T10:15:00Z"
}
```

Ответ `400 Bad Request` (заголовок слишком короткий):

```json
{ "error": "validation", "message": "Проверьте поля", "fields": { "title": "От 5 до 80 символов" } }
```

### Назначить редактора

`PATCH /api/publication-requests/1/assignee`

```json
{ "assigneeUserId": 3 }
```

Ответ `200 OK` — заявка целиком, `assigneeUserId: 3`, статус остаётся `New`.

Ответ `404 Not Found`:

```json
{ "error": "not_found", "message": "Заявка 999 не найдена" }
```

### Сменить статус

`PATCH /api/publication-requests/1/status`

```json
{ "status": "InProgress" }
```

Ответ `200 OK` — заявка целиком, `status: "InProgress"`.

Ответ `409 Conflict` (попытка вернуть опубликованную заявку в работу):

```json
{ "error": "conflict", "message": "Нельзя перевести заявку из Closed в InProgress" }
```

### Список заявок

`GET /api/publication-requests?status=New`

Ответ `200 OK`: массив объектов в том же формате, что и ответ на создание, или `[]`.

### Справочник подразделений

`GET /api/departments`

```json
[
  { "id": 1, "name": "Учебный отдел" },
  { "id": 4, "name": "ИТ-служба" }
]
```

## Вход и права (появится в ЛР11)

До ЛР11 сервер подставляет в `createdByUserId` тестового автора. С ЛР11:

| Действие | Кто может | Иначе |
|----------|-----------|-------|
| `POST /api/auth/login` | все | `401` при неверном логине или пароле |
| `POST /api/publication-requests` | автор | `403` |
| `PATCH …/assignee` | координатор | `403` |
| `PATCH …/status` | только назначенный редактор | `403` |
| `GET /api/publication-requests` | автор — свои, редактор — назначенные ему, координатор — все | — |
| любой запрос без входа (кроме `/api/auth/login`) | — | `401` |
