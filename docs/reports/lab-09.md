## 1. Цель

Данные проекта описаны схемой PostgreSQL: три таблицы со связями, четыре статуса, ограничения и индексы. Учебные данные позволяют проверить фильтр, `JOIN` и `GROUP BY`, а схема совпадает с моделью из `docs/data-model.md`.

## 2. Что сделали

1. `db/schema.sql` — таблицы `departments`, `users`, `publication_requests`; PK, FK, `CHECK` на статусы и роли, `UNIQUE` на номер и логин, три индекса с комментариями.
2. `db/seed.sql` — 4 подразделения, 3 пользователя, 5 заявок: представлены все четыре статуса.
3. `db/queries.sql` — шесть запросов: фильтр с сортировкой, `JOIN` со справочником, `GROUP BY` по статусам, `LEFT JOIN` с пользователями, `GROUP BY` по подразделениям и закомментированная проверка `CHECK`.
4. Повторный прогон схемы безопасен: в начале `DROP TABLE IF EXISTS … CASCADE` в правильном порядке.

## 3. Запуск

```bash
createdb kb_kgeu
psql -d kb_kgeu -f db/schema.sql
psql -d kb_kgeu -f db/seed.sql
psql -d kb_kgeu -f db/queries.sql
```

Пароль вводится интерактивно и в репозиторий не попадает.

## 4. Доказательство успеха

| Что проверяли | Результат |
|---|---|
| схема применяется | таблицы созданы, ошибок нет |
| повторный прогон `schema.sql` | проходит без ошибок, таблицы пересозданы |
| фильтр `status = 'New'` с сортировкой | 2 строки, новая сверху |
| `JOIN` со справочником | в выводе названия подразделений, а не только `department_id` |
| `GROUP BY status` | 4 группы: `Cancelled` 1, `Closed` 1, `InProgress` 1, `New` 2 |
| `GROUP BY` по подразделениям | Деканат 2 заявки (1 ожидает), остальные по 1 |

Пример результата `GROUP BY`:

```text
   status   | count
------------+-------
 Cancelled  |     1
 Closed     |     1
 InProgress |     1
 New        |     2
```

Ошибочная вставка оставлена в `queries.sql` закомментированной и в `seed.sql` не входит.

## 6. Проверка 3НФ

Название подразделения хранится один раз в таблице `departments`; заявка ссылается на него числом `department_id`. При переименовании подразделения меняется одна строка, а не все заявки. ФИО автора и редактора лежат только в `users`, в заявке — `created_by_user_id` и `assignee_user_id`.

## 7. Индексы

| Индекс | Какой запрос ускоряет |
|---|---|
| `publication_requests_status_idx` | список «заявки в статусе New» |
| `publication_requests_department_id_idx` | фильтр по подразделению и `JOIN` со справочником |
| `publication_requests_assignee_user_id_idx` | экран редактора «мои заявки» |
