## 1. Название и организация

- Название системы: **«База знаний КГЭУ»**, модуль согласования и публикации материалов
- Организация / подразделение: Казанский государственный энергетический университет (КГЭУ). Заказчик — координатор базы знаний университета. Авторы материалов — сотрудники подразделений (учебный отдел, деканаты, студенческий городок, ИТ-служба, международный отдел, библиотека)
- № из таблицы примеров: своя тема (тема ВКР №6 из списка кафедры: «Разработка интеллектуальной базы знаний университета на основе внутренних регламентов, инструкций и цифровых сервисов»)

## 2. Главная сущность и справочник

- Главный объект (одна запись процесса): **заявка на публикацию материала** в базе знаний (инструкция, порядок действий, ответ на частый вопрос)
- Справочник (вторая таблица, ссылка числом): **подразделение**, которое отвечает за материал
- Поле-ссылка (как назовёте в JSON/БД): `departmentId`

## 3. Роли и права

| Роль | Создаёт | Назначает | Меняет статус |
|------|---------|-----------|---------------|
| Автор (сотрудник подразделения) | да | нет | нет |
| Координатор базы знаний | нет | да | нет |
| Редактор базы знаний | нет | нет | да, только у заявок, назначенных ему |

Редактор не назначает себя сам. Назначает только координатор.

## 4. Сценарий в одно предложение

Сотрудник учебного отдела подаёт заявку «Порядок оформления академического отпуска» → координатор назначает редактора → редактор берёт заявку на проверку и публикует материал или отклоняет его.

## 6. Что не входит в семестр

1. ИИ-помощник и поиск по смыслу (это ВКР)

3. Редактор полного текста материала и публичная страница базы знаний
4. Уведомления по почте и в мессенджерах
5. Вход через единую учётную запись университета, интеграция с сайтом КГЭУ и ЭИОС
6. Мобильное приложение

## 7. Запас под ВКР

**Данные / процесс**

1. Хранение полного текста опубликованного материала с версиями и сроком пересмотра. Когда срок истекает, система сама создаёт заявку на пересмотр.
2. ИИ-помощник на основе RAG: отвечает только по материалам со статусом «Опубликовано» и указывает источник. Если ответа нет, называет подразделение из справочника, куда обратиться.
3. Вопросы, на которые помощник не ответил, автоматически становятся заявками на новый материал для нужного подразделения.

**Связи с другими системами**

4. Импорт регламентов и инструкций с сайта КГЭУ (PDF/DOCX): разбиение на фрагменты и векторная индексация в PostgreSQL (pgvector).
5. Передача нерешённого вопроса в Service Desk университета; ссылки из ответов на цифровые сервисы (ЭИОС, личный кабинет).

**Масштаб**

6. Доступ к материалам по ролям (студент / преподаватель / сотрудник), журнал запросов к помощнику, защита персональных данных по 152-ФЗ.
7. Оценка качества ответов на наборе из ~100 реальных вопросов: доля верных ответов, верная ссылка на источник, доля правильных отказов.

## 8. Чем не копия соседа

Ближайшие темы из списка кафедры (№7, №8, №9) и пример №9 из методички («Обращения в деканат») строятся вокруг **обращения пользователя** о проблеме. У меня главный объект — **материал базы знаний** и его согласование перед публикацией. Роли тоже другие: автор, координатор и редактор базы знаний, а не заявитель и исполнитель обращения. Результат процесса — проверенный материал, на который потом опирается ИИ-помощник.
