Роли взяты из ТЗ (`lab-01-requirements.md`): автор подаёт заявку, координатор назначает редактора, редактор проверяет материал.

---

## Кто что может

| Действие | Автор | Координатор | Редактор | Гость |
|---|---|---|---|---|
| Войти (`POST /api/auth/login`) | да | да | да | да |
| Список заявок (`GET /api/publication-requests`) | да | да | да | нет → 401 |
| Одна заявка (`GET /api/publication-requests/{id}`) | да | да | да | нет → 401 |
| Создать заявку (`POST /api/publication-requests`) | да | нет → 403 | нет → 403 | нет → 401 |
| Назначить редактора (`PATCH /{id}/assignee`) | нет → 403 | да | нет → 403 | нет → 401 |
| Сменить статус своей заявки (`PATCH /{id}/status`) | нет → 403 | нет → 403 | да | нет → 401 |
| Сменить статус чужой заявки | нет → 403 | нет → 403 | нет → 403 | нет → 401 |
| Список редакторов (`GET /api/users?role=Editor`) | нет → 403 | да | нет → 403 | нет → 401 |

«Своя заявка» для редактора — та, где `assignee_user_id` равен его `id`.

## Где проверяется

| Проверка | Код |
|---|---|
| вход выполнен | `[Authorize]` на контроллере, cookie-схема в `Program.cs` |
| роль подходит | `[Authorize(Roles = ...)]` на действии |
| заявка принадлежит редактору | `PublicationRequestService.ChangeStatus`, сравнение `AssigneeUserId` с id из claims |
| правила перехода статуса | `RequestStatus.CanMove` + проверка назначенного редактора |

Кнопка, спрятанная на экране, правом не является: тот же запрос через Swagger или curl получает 401 или 403.

## Коды ответов

| Код | Смысл | Пример |
|---|---|---|
| 401 | сервер не знает, кто это | `POST` заявки без входа |
| 403 | личность известна, действие запрещено | автор назначает редактора |
| 409 | правило процесса нарушено | статус `InProgress` без назначенного редактора |

## Пароли

Пароли хранятся только как хэш `PasswordHasher<User>` из ASP.NET Core Identity (соль и стоимость внутри библиотеки). В таблице `users` лежит строка вида `AQAAAAIAAYagAAAAE...`, которая не равна паролю и не раскодируется из Base64.

Учебные учётные записи стенда (только локально, см. README):

| Логин | Роль | Пароль |
|---|---|---|
| `author` | автор | `Author-2026` |
| `coordinator` | координатор | `Coordinator-2026` |
| `editor` | редактор | `Editor-2026` |

## Безопасный вывод

Описание заявки выводится обычной подстановкой React (`{item.description}`), поэтому текст `<script>alert(1)</script>` показывается символами и не выполняется. `dangerouslySetInnerHTML` в проекте не используется — это аналог запрета `v-html` из методички.
