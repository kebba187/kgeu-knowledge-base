## D-01. Нет страницы одной заявки

- **Шаги / ожидали / получили:** в списке нет перехода к карточке заявки; `GET /api/publication-requests/{id}` работает, но экрана для него нет.
- **Причина:** по методичке в семестре нужны три экрана: список, создание, вход.
- **Исправление:** добавить маршрут `/requests/:id` и страницу с историей статусов.
- **Повторная проверка:** не проводилась.
- **Статус:** открыт, вынесен в запас ВКР.

## D-02. Названия подразделений продублированы на клиенте (исправлено)

- **Шаги / ожидали / получили:** `GET /api/departments` отдаёт справочник, но форма создания берёт подписи из `frontend/src/dictionaries.js`.
- **Причина:** подписи добавлены в ЛР3, когда сервера ещё не было, и после ЛР12 остались как есть.
- **Исправление:** ответ API получил поля `departmentName`, `createdByFullName` и `assigneeFullName` — их подставляет `JOIN` в проекции. Форма создания загружает справочник через `GET /api/departments`, список подразделений из `frontend/src/dictionaries.js` удалён; в файле остались только подписи статусов, которые относятся к экрану, а не к данным.
- **Повторная проверка:** в таблице видно название подразделения и ФИО редактора; в форме создания подразделение выбирается из выпадающего списка, полученного с сервера.
- **Статус:** закрыт.

## D-03. Учебные пароли в README

- **Шаги / ожидали / получили:** в README перечислены логины и пароли трёх учебных учёток.
- **Причина:** методичка ЛР11 это допускает для локального учебного контура.
- **Исправление:** вне учебного стенда учётные записи заводятся отдельно, пароли в репозиторий не попадают.
- **Повторная проверка:** `git grep` по паролям и строкам подключения — секретов нет, строка подключения только в user-secrets.
- **Статус:** закрыт как осознанное ограничение.

## D-05. Несуществующее подразделение давало 500 (исправлено)

- **Шаги / ожидали / получили:** `POST` с `departmentId = 99` ожидали `400`; получали `500` от внешнего ключа базы.
- **Причина:** существование подразделения проверял только внешний ключ, на уровне сервиса проверки не было.
- **Исправление:** `PublicationRequestService.Create` проверяет справочник через `IDepartmentStore` и возвращает `400` с полем `departmentId`.
- **Повторная проверка:** `POST` с `departmentId = 99` → `400`, тело `{"fields":{"departmentId":"Такого подразделения нет в справочнике"}}`; с `departmentId = 2` → `201`.
- **Статус:** закрыт.
